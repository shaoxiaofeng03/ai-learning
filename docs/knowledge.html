全景一个请求的完整路径

浏览器
  │  GET /echo?text=hi  或  POST /echo {"text":"hi"}
  ▼
路由匹配        @app.get / @app.post
  ▼
参数校验        Query() / BaseModel  ──失败──▶ 422
  ▼
处理函数        你的业务代码
  ▼
响应序列化      response_model
  ▼
JSON 返回

记法：路由 → 校验 → 业务 → 序列化。中间任何一步失败，都在校验层返回 422。

K1Web 框架与路由

对应 Java：Spring MVC

一句话：装饰器在导入时把函数注册进路由表，请求来了按「方法 + 路径」匹配。
  1. FastAPI() 是应用对象，内部持有路由表，等价 @SpringBootApplication。
  2. @app.get("/echo") 在模块导入时执行注册，不是每次请求都注册。
  3. response_model 做三件事：过滤多余字段、生成 OpenAPI 文档、决定返回结构。
  4. APIRouter 把路由拆到不同文件，等价 @RestController 分模块。
  5. HTTP 方法决定语义：GET 查询、POST 提交、PUT 全量更新、PATCH 局部更新、DELETE 删除。
FastAPISpring
@app.get@GetMapping
Query()@RequestParam
BaseModel 作入参@RequestBody + @Valid
APIRouter@RestController
校验失败返回 422（Unprocessable Entity），不是 400。400 一般留给「请求格式本身坏了」。

口诀：入参看位置（URL 还是 body），出参看模型。

自测：response_model 和函数返回类型注解，作用一样吗？

不完全一样。返回类型注解用于类型提示和文档推断；response_model 额外做字段过滤和序列化控制。两者都写时以 response_model 为准。

K2类型系统与校验

对应 Java：DTO + Bean Validation

一句话：注解只是说明书，pydantic 才是门卫。
  1. Python 的类型注解运行时完全不检查，只是给 IDE、ruff、pydantic 看的元数据。
  2. pydantic 在构造模型时校验，失败抛 ValidationError，FastAPI 转成 422。
  3. 字段类型写成另一个 BaseModel，自动递归校验，不需要 @Valid。
  4. 金额用 Decimal，不用 float（二进制浮点有精度误差）。
  5. 派生字段（总额、均价）必须服务端算，用 @computed_field。
  6. 自定义规则用 @field_validator，对应 Java 的自定义 ConstraintValidator。
Javapydantic v2
@NotNull非 Optional 且无默认值
@NotBlankField(min_length=1) + validator 去空格
@Min/@MaxField(ge=, le=)
@SizeField(min_length=, max_length=)
@PatternField(pattern=r"...")
min_length=1 拦不住 " "。空格字符串长度是 1，必须 strip() 后再判断。

口诀：gt/ge/lt/le = 大于/大于等于/小于/小于等于。金额 gt，数量 ge。

422 长什么样

{
  "detail": [{
    "type": "greater_than_equal",
    "loc": ["body", "items", 0, "qty"],
    "msg": "Input should be greater than or equal to 1",
    "input": 0
  }]
}

记法：loc 是字段路径，body 之后依次是模型字段、数组下标。对应 Java 的 BindingResult。

自测：嵌套模型需要额外写校验注解吗？

不需要。字段类型是 list[OrderItem] 时，每个元素都走 OrderItem 的校验规则，错误路径带上下标。

K3列表推导与生成器

对应 Java：Stream

一句话：方括号一次算完，圆括号用到才算。
  1. [f(x) for x in xs if cond] 等价 stream().filter().map().collect()。
  2. {k: v for ...} 生成字典，{x for ...} 生成集合。
  3. 生成器 (f(x) for x in xs) 是惰性的，不占内存，一次只产出一个。
  4. 生成器只能遍历一次，遍历完就空了，也没有 len() 和下标。
  5. yield 用来写生成器函数，等价返回 Iterator。
  6. itertools.groupby 要求输入已排序，否则同组会被拆散。
nums = [1, -2, 3, -4]
print([x * 2 for x in nums if x > 0])   # [2, 6]

def read_lines(path: str):
    with open(path, encoding="utf-8") as f:
        for line in f:
            yield line.strip()

gen = (x * 2 for x in nums)
print(list(gen))   # [2, -4, 6, -8]
print(list(gen))   # []  第二次就空了
需要长度、需要多次遍历、需要随机访问 → 用列表。数据大于内存、只需要顺序处理一次 → 用生成器。

口诀：列表是「一次性做好一桌菜」，生成器是「吃一口上一口」。

自测：生成器表达式和列表推导，内存差在哪？

列表推导立刻把所有结果放进内存；生成器只保存当前状态，处理 100 万行时内存几乎恒定。

K4async / await 与事件循环

对应 Java：CompletableFuture

一句话：async 是「一个服务员同时接十桌」，不是「请十个服务员」。
  1. async def 定义协程函数，调用它得到协程对象，不会立即执行。
  2. await 把控制权交还事件循环，等 IO 完成再回来。
  3. 单线程 + 事件循环 + 协作式调度，不是多线程。
  4. 只加速 IO 密集；CPU 密集不会变快，因为没有并行计算。
  5. asyncio.gather 并发等待多个协程，等价 CompletableFuture.allOf。
  6. 同步函数里不能 await；阻塞调用（time.sleep、requests、大循环）会卡死整个事件循环。
Java 线程池Python asyncio
多线程，OS 调度单线程，用户态调度
切换微秒级切换纳秒级
CPU + IO 都能并行只有 IO 能并发
allOfgather
async def work(i: int) -> int:
    await asyncio.sleep(1)
    return i * i

results = await asyncio.gather(*(work(i) for i in range(10)))
# 10 个耗时约 1 秒，不是 10 秒

口诀：await 是排队等外卖，等的时候可以去洗菜；但厨师只有一个。

自测：CPU 密集任务怎么处理？

用 ProcessPoolExecutor 或多进程，绕开 GIL；或者把计算交给其他服务。async 解决不了。

K5异步 HTTP 与并发控制

对应 Java：HttpClient + Semaphore

一句话：限流、超时、复用，一个都不能少。
  1. 异步请求用 httpx.AsyncClient；requests 是同步的，会阻塞事件循环。
  2. 一个 AsyncClient 复用连接池，不要每次请求都新建。
  3. asyncio.Semaphore(n) 限制同时在飞的请求数，对应 Java Semaphore。
  4. 超时必须显式设置，否则一个慢请求拖垮整批。
  5. 重试要配合幂等：只有 GET / PUT 这类可以安全重试，POST 要小心重复下单。
  6. 遇到 429 要退避（指数 + 随机抖动），不要硬怼。
sem = asyncio.Semaphore(5)
async with httpx.AsyncClient(timeout=5.0) as client:
    async def one() -> int:
        async with sem:
            r = await client.get("http://127.0.0.1:8000/health")
            return r.status_code
    codes = await asyncio.gather(*(one() for _ in range(20)))

口诀：Semaphore 管人数，timeout 管耐心，Client 复用管成本。

自测：为什么 POST 重试可能出问题？

POST 通常不幂等。第一次请求其实成功了但响应丢了，重试会再创建一次，导致重复订单。解决：幂等键（idempotency key）。

K6工程习惯

对应 Java：Maven + JUnit + Checkstyle

一句话：依赖用 uv，测试用 pytest，格式用 ruff。
  1. uv sync 按 pyproject.toml + uv.lock 装依赖，等价 mvn install。
  2. uv run ruff check . 静态检查，ruff format . 格式化。
  3. pytest 用 test_*.py 命名发现用例，函数名也以 test_ 开头。
  4. 路由分文件（routers/），模型抽到 schemas.py，不要在多个文件重复定义。
  5. 配置走环境变量 + pydantic-settings，.env 不进 git。
uv sync
uv run pytest -q
uv run python -m uvicorn week01.app.main:app --reload
ruff check . && ruff format .

口诀：能自动检查的，绝不用眼睛看。

自测：为什么模型要抽到 schemas.py？

同一份数据结构被多处使用时，重复定义会导致改一处漏一处。抽出来单一来源，也方便测试。

?抽背 24 题

先自己答，再展开对照。连续两次答对再勾「已掌握」。

1. Python 的类型注解运行时会检查吗？

不会。只是元数据，pydantic 才会校验。

2. 校验失败返回什么状态码？错误在哪？

422，错误列表在 detail，字段路径在 loc。

3. GET 和 POST 怎么选？

无副作用的查询用 GET；有副作用、长文本、敏感数据用 POST。

4. response_model 有什么作用？

过滤字段、生成文档、决定序列化结构。

5. 嵌套模型需要写 @Valid 之类的注解吗？

不需要，类型是 BaseModel 就自动递归校验。

6. @NotBlank 对应 pydantic 的什么？

Field(min_length=1) 加 @field_validator 去空格，单靠前者拦不住纯空格。

7. gt=0 和 ge=0 的区别？

gt 大于 0，ge 大于等于 0。金额用 gt，数量用 ge。

8. 为什么金额用 Decimal？

float 是二进制浮点，0.1+0.2≠0.3，累计会有分位误差。

9. total 为什么不让客户端传？

客户端可伪造。金额必须服务端根据明细计算。

10. 列表推导等价于 Java 的什么？

stream().filter().map().collect()。

11. 生成器能遍历几次？

一次。遍历完就空了，也没有 len() 和下标。

12. 什么时候必须用生成器？

数据大于内存、只需顺序处理一次、流式读取。

13. itertools.groupby 有什么前提？

输入必须先排序，否则同组会被拆成多段。

14. async 是多线程吗？

不是。单线程 + 事件循环 + 协作式调度。

15. async 能加速 CPU 密集任务吗？

不能。需要多进程或换方案。

16. await 到底做了什么？

把控制权交还事件循环，等 IO 完成后再恢复执行。

17. asyncio.gather 对应 Java 的什么？

CompletableFuture.allOf。

18. 在 async 函数里用 requests 会怎样？

阻塞整个事件循环，所有协程一起卡住。要用 httpx.AsyncClient。

19. Semaphore 解决什么问题？

限制同时进行的请求数，防止打爆对方或耗尽连接池。

20. 为什么不每次请求都新建 Client？

连接池无法复用，握手开销大，性能和资源都浪费。

21. 为什么 POST 重试要小心？

POST 通常不幂等，可能重复创建。要用幂等键。

22. 一个请求进来依次经过哪几步？

路由匹配 → 参数校验 → 业务处理 → 响应序列化。

23. APIRouter 对应 Spring 的什么？

@RestController 分模块。

24. uv / pytest / ruff 分别对应 Java 的什么？

Maven / JUnit / Checkstyle。
